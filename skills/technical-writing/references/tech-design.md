# 技术方案模式编写指南

面向研发评审与工程落地。读者关心**改哪里、怎么实现、如何复用现有代码、配置与协议怎么定、边界和异常怎么兜底、按什么顺序安全上线**，不写空泛背景。

## 语气与写法基调

- **极简务实、零寒暄**：结论和改造点直接落地，常用短句与清单表达。
- **明确复用锚点与差异**：复用或参考已有实现时，直接写出参考文件/函数名（如“参考 `xx.go` 中的 `yy`，其余部分沿用，本次仅改 zz”），不重复展开旧逻辑。
- **风险与约束显式标出**：对双端同值约束、两处维护带来的语义漂移风险、匹配顺序短路、多阶段字段覆盖等，用引用块（`>`）或高亮块（`<callout>`）直接提示。

## 推荐文档结构（按实际问题裁剪）

1. **需求与关联材料**
   - 直接引用 PRD、联调记录或前置分析文档链接，不抄写需求全文。
2. **需求拆分与全局概览**
   - 几句话交代本次改造主线及分阶段节奏（如 `dryrun → AB 实验 → 推全 → 存量回扫`）。
   - 列出**接入范围**（产品、链路/场景、地区口径）与**策略/标签优先级表**。
   - 若存在多条识别或执行路径，先用简明流程图对齐方案收敛关系（例如“路径一可视为路径二的特例，统一实现”）。
3. **开发改造（按链路或跨端服务边界拆解）**
   - 跨服务改动按调用链分段（如 `上游生产消息 → 中游消费处理 → 下游回调处置`；如有读侧/消费侧配合，单列实验或过滤改造小节），明确各服务职责边界。
   - **图形化链路与位置对照**：解释调用链、决策流转或多条链路接入位置时，优先使用**画板（Whiteboard）**或双栏并列流程图标明新旧节点相对顺序（如用 `新` 标记新增模块），替代大段文字描述；若在飞书等富文档工具中编写，直接调用对应画板与分栏模块。
   - **可对照落地的核心代码**：给出关键结构体、函数签名与核心控制流/实现骨架，在注释中写清设计意图、兜底原因和跨端约定（避免贴大段无关样板代码）。
4. **协议、动态配置与写入字段**
   - **IDL 与消息协议**：给出 IDL/Struct 新增字段、MQ/HTTP 字段语义表、完整 JSON 示例，以及上游字段到下游回调字段的映射表。
   - **动态配置明细**：写明配置平台与载体（如 TCC / Dolphin / 规则中心）、key 命名、规则顺序表（`顺序 | 规则名 | 表达式 | 返回结果`）、生效区域与安全初始值（如初始放量 0%、默认动作 dryrun）。
   - **多阶段写入/副作用对照**：当涉及 `dryrun / abtest / punish / compute_only / backscan` 等多种执行模式时，用表格列出各模式写入字段、是否触发真实处置，并附上对应的 JSON 示例；有多个规则先后命中时，写明字段保留或覆盖优先级。
5. **放量、AB 实验与错误处理**
   - 说明灰度放量分桶算法（如按主 ID 取模保持同一对象稳定）、计算时机、以及 `compute_only / backscan` 等模式的放量豁免规则。
   - 交代 AB 实验开关读取路径、实验组/对照组行为、双端同值键约束及豁免条件（如作者本人豁免）。
   - **错误处理与强弱依赖分级**：按投递、消费、回调等环节分别列明**跳过/降级错误**（记录日志后继续或返回成功）与**强依赖错误**（向上报错或返回 500 触发重试）。
6. **指标与看板**
   - 用表格列出指标设计（`指标名 | 维度与口径 | 观测作用`），**注意把“规则正常命中/放行”与“配置缺失/解析降级（如 `judge_fail` / `skip_no_config`）”拆成不同维度值**，让配置漏配可被直接监控发现。
   - 附看板链接、核心筛选变量及异常排查组合（如结合错误 QPS 与失败率判断，避免放量波动干扰）。
7. **存量回扫与量级评估（如涉及存量处理）**
   - 明确回扫口径与边界（如是否包含已处置历史数据），给出统计 SQL/盘点数据，并基于下游 QPS 上限计算不同 QPS 下的**耗时量级估算表**，提示与线上流量的资源竞争。
8. **Timeline、Checklist 与接入顺序**
   - Checklist 覆盖配置、权限、开发、看板、dryrun、实验、推全、回扫等全链路事项。
   - 按依赖顺序列出可执行的上线步骤（如先 IDL → 再消费/回调服务 → 再生产端与配置规则 → 低比例 dryrun 验证 → 切 punish 与回扫）。
   - 若方案尚有未拍板的边界问题，可集中列出待确认清单；定稿时将已确认项直接收敛进正文结论。

## 细节取舍标准

- **必须写透的内容**：影响业务语义或线上正确性的边界条件（如按顺序命中、大小写匹配行为、解析容错约定、只加载命中后所需上下文的延迟加载策略）。
- **概括处理的内容**：常规字段校验、基础格式转换、已声明照抄的既有 loader/helper 内部细节。

## 画板绘制规范（极简原生流程图）

绘制或审校技术方案画板时，先查看示例图确认风格：
- 多路径对照：[多路径对比示例](examples/tech-flow-compare.jpg)
- 跨链路异步与回调：[异步回调链路示例](examples/tech-async-callback.jpg)

绘制要求：
- **严格极简原语**：只用基础几何框、菱形判断、圆柱存储、分区容器与连线箭头；**禁用装饰性图标、角标及过度拆碎的独立文本框/多层叠加卡片**，保证高信噪比与低改图成本。
- **图形表达语义、节点只留短词**：用分区、流向、实虚线（如实线主流程 vs 虚线异步/回调、虚线框=复用基建）和少量色彩直接表达因果与边界；禁止在画板上放长段文字解释或大块说明气泡，完整参数与规则留给正文和表格。
- **防止排版挤压**：控制单图节点数量，避免窄框文字多行拥挤或连线穿越文字/分区标题。
