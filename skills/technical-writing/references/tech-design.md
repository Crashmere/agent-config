# 技术方案模式编写指南

面向研发评审与工程落地。读者关心**方案是否成立、边界与风险在哪、改哪些端、怎么配置上线**，而不是背景抒情。

## 语气与表达

- **直白务实、零寒暄**：去掉铺垫与客套，结论和改动点直接落地。
- **复用直接声明**：复用已有算法、底座或模块时，一句话交代复用对象与本次扩展点，不重复展开旧逻辑。
- **显式标注约束与风险**：对跨端一致要求、维护风险、边界条件和临时妥协，用引用块（`>`）或高亮块（`<callout>`）直接标出，例如双端同值约束、两处维护导致的语义漂移风险、按顺序命中短路等。

## 推荐文档结构

按实际问题复杂度裁剪章节，无需为凑齐标题而填空：

1. **需求与关联材料**
   - 直接引用需求文档（PRD）和前置分析文档链接，不重复抄写业务背景全文。
2. **需求拆分与全局概览**
   - 先用简短条目说清本次改造主线与分阶段上线节奏（如 `dryrun → AB 实验 → 推全 → 存量回扫`）。
   - 明确**接入范围**（产品、链路/场景、地区口径）与**策略/标签优先级表**。
   - 如有多种识别或执行路径，用简要流程图或文字链路先对齐全局，再进入各端开发细节。
3. **开发改造（按服务或链路拆解）**
   - 跨服务方案按上游、中游、下游分节（如生产消息 → 消费处理 → 回调处置），明确每端职责边界。
   - **链路位置对照**：多条链路同时接入时，优先使用并列双栏展示各链路节点顺序，并用 `新` 等标记标出新增模块与上下游相对位置。
   - **核心逻辑与数据结构**：只贴决定业务语义、优先级、上下文传递、分支短路和异常语义的结构体、关键函数或逻辑示意代码；在代码注释中说明设计意图与约束，不粘贴大段无信息量的样板代码。
4. **协议、配置与写入字段**
   - **接口与消息协议**：给出 IDL/Struct 变更、MQ/HTTP 请求字段表及完整 JSON 示例，并附消费侧与回调侧字段映射关系。
   - **分阶段写入/状态对照表**：涉及多阶段（如 dryrun、机审、反转送人审、AB 实验、人审）写入不同字段或状态时，用三列表「阶段 | 字段规则 | 写入 JSON 示例」并排对齐。
   - **动态配置**：明确配置载体（如 TCC / Dolphin / 规则中心）、key 命名、默认回退值及配置生效范围。
5. **放量、AB 实验与错误处理**
   - 说明灰度放量口径、分桶方式、计算时机与重放/回扫时的特殊行为。
   - 交代 AB 实验参数、实验组/对照组开关读取逻辑及豁免条件（如作者本人豁免）。
   - **错误处理与依赖分级**：按投递、消费、回调等阶段分别列出**强依赖（向上报错触发重试）**与**弱依赖/可跳过错误（记录后降级或跳过）**的边界。
6. **指标与看板**
   - 用表格列出新增或复用的监控指标（`指标名 | 维度与口径 | 观测关注点`），明确哪些曲线异常对应哪类配置或下游故障，并附看板链接与关键筛选变量说明。
7. **存量回扫与量级评估（如涉及存量处理）**
   - 明确回扫对象范围与过滤条件，附上口径统计查询（如 SQL）和基于下游 QPS 上限的**耗时量级估算表**（不同 QPS 对应天数/小时数），提示线上流量与回扫并发的相互影响。
8. **Timeline、Checklist 与接入顺序**
   - 用任务清单列出代码、配置、权限、看板、dryrun、实验、推全与回扫项。
   - 按接口与配置依赖顺序列出可执行的上线/接入步骤，并写明初始安全配置（如初始放量比例为 0、初始动作设为 dryrun）。

## 排版与细节取舍

- **表格优先的场景**：策略优先级、协议字段表、阶段写入字段对照、监控指标口径、QPS 耗时估算。
- **代码块优先的场景**：IDL 定义、请求/配置 JSON 示例、关键状态流转与核心逻辑示意。
- **常规逻辑概括处理**：日常参数解析、格式转换、常规字段校验只需一句带过；但**一旦漏写会导致误解或双端实现不一致的规则**（如字段解析容错约定、大小写匹配行为、空列表默认语义、异常码映射），必须用高亮块或列表写清楚。
