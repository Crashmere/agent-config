# 叙述汇报模式编写指南

面向管理层汇报、专项综述、项目复盘、收益分析与阶段答辩。目标是让读者在有限时间里看懂四件事：**业务为什么需要做、难在哪里、方案怎么解决的、拿到了什么实打实的收益**。

## 视角与语气

- **从业务出发，在系统和流程层讲清楚**：先交代业务水位和变化，说明这对研发提出了什么要求，再讲系统架构、流程和契约怎么改。**不罗列文件路径、函数签名或常量定义**；只有精确指明某个具体接口的失败率、某条策略的准确率变化时，才保留必要的接口名或策略名。
- **直白紧凑，不写口语开场**：删掉“大家好，”“下面我来介绍一下……”这类念稿词，直接写成既能看懂、又能当讲解底稿的书面内容；同时也**别堆“赋能、抓手、闭环、范式迁移”等汇报黑话**，把机制和变化用大白话讲透。
- **如实说边界和未决问题**：成果要讲清，阶段边界、改造代价、负向实验结论和暂缓事项也要坦诚写明（例如某个核心指标出现负向后按结论暂停扩量、某个方案因排期暂缓）。

## 两种常见结构（按文档类型选用）

### 形态一：单专项综述 / 改造汇报
适合围绕一个大型改造或治理专项讲透：
1. **背景与痛点**：业务现状与核心指标水位 → 现有链路出了什么问题 → 用「问题分类 | 现状 | 具体痛点（带来什么后果）」表把痛点摊开。
2. **目标与边界**：用双栏表对比「长期目标 vs 本次改造」，说清谁来操作、研发还要不要介入、耗时能降多少、要多维护什么成本。
3. **核心设计与验证**：讲清楚为什么选当前载体和架构（详细技术方案挂外链）；单列一节说清上线怎么保稳（如 `PPE 单点自测 → 线上双跑只读对比 Diff → 分步切流`）、对上下游口径有什么影响，以及配套的维护工具。
4. **改造前后对比**：用「改造前 vs 改造后」双栏画板或对照说明，让人一眼看出结构变化（例如从“边算边写、互相覆盖”变成“先算完、再统一写一次”）。
5. **改造收益**：用高亮块（`<callout>`）把核心机制和改造前后的数据对比收口。

### 形态二：多项目总结 / 阶段答辩汇报
适合汇总一段时间内的多项能力建设、策略治理和线上优化：
1. **业务背景与演进主线**：用简短的话说清业务在做什么、由此带来哪些**对研发侧的核心要求**，再用「阶段 | 核心目的 | 关键动作 | 当前进度」表把整体时间线串起来。
2. **按主题拆分子项目**：按能力建设、策略调整、底座复用、稳定性优化等板块组织，每个子项目按复杂度选一种展开方式：
   - **单能力攻坚**：几句背景 +「难点 | 解决方式」两栏表（可配画板或监控图）+ 业务侧收益 / 技术侧收益 / 协作收益 + 后续计划；
   - **多子项并列**：1～2 条背景目标 +「子项目 | 核心做法 | 收益」三栏总览表 + 和后续工程演进的关系；
   - **线上排查 / 调研**：四行结构表「问题现象 → 排查与定位（先写怎么排除误判，再定位真因）→ 解决与收益 → 下一步」。

## 证据、图表与外链

- **机制配硬数据**：所有“变快、省人力、更准、更稳”的说法，必须绑定具体机制和前后数字（例如交付周期从 `0.5～1 天` 压到 `2～15 分钟`、同类需求 `80%` 不用改代码发版、失败率从 `20%～30%` 降到 `5%` 以下、每周无效放出少 `57.7%`、下游 `11` 个模型 0 改动），不写空形容词。
- **画板与特殊模块优先**：灵活使用**画板（Whiteboard）、高亮块（Callout）、双栏对比和表格**。复杂流程或前后对比直接画板表达；监控折线图、命中率/内存成本柱状图紧贴对应的排查过程或选型测算放置。
- **表格收口、外链分流**：带多个属性或对比维度的内容收成表格，少用多层嵌套无序列表；完整技术方案、SQL 测算、归因分析和看板放引用链接，保持正文清爽好扫读。

## 画板绘制规范（高层对比与分阶段视角）

画或改叙述汇报画板前，先看示例图对齐风格：
- 红绿改造前后对比：[改造前后架构对比示例](examples/report-before-after.jpg)
- 多阶段行为与副作用泳道：[四阶段对比泳道示例](examples/report-stage-lanes.jpg)

绘制要求：
- **允许对比卡片，不要花哨装饰**：可以做红绿“改造前 vs 改造后”卡片或分阶段并列泳道，但**不用无意义装饰图标（纯点缀 icon、徽章、角标圆点）和过度拆碎的叠加文本框/编组**，保留清晰度和后续改图空间。
- **保持高层视角、靠视觉对比讲收益**：画板同样不塞代码细节，用颜色、实虚线和左右/上下对照让读者直接看出**老做法卡在哪、新做法怎么改、省了什么事**（例如红框/虚线标出冲突和回擦，绿框标出统一执行和提效；实线框与虚线框区分改不改线上状态）。
- **少字多图意、一眼看懂**：节点里只写极简短语和关键数字，完整解释留在正文或表格，确保打开图就能直接看懂意图。
