# 技术方案模式编写指南

面向研发评审与工程落地。读者关心的是：**改哪里、怎么实现、复用哪块老代码、协议和配置怎么定、边界和异常怎么兜底、按什么顺序安全上线**，开篇直入主题。

## 语气与写法

- **直白务实、少绕弯**：直接说结论和改法，多用短句、具体动词和清单，不写书面黑话和寒暄。
- **指明复用哪份老代码和差异**：复用或照抄已有实现时，直接写出参考文件/函数名（如“参考 `xx.go` 的 `yy`，其余沿用，本次只改 zz”），不把旧逻辑重写一遍。
- **把坑和约束直接标出来**：双端必须同值的 key、两处维护容易漂移的逻辑、按顺序命中短路、多阶段字段覆盖规则等，用引用块（`>`）或高亮块（`<callout>`）直接标明。

## 推荐章节（按问题大小增删，不硬凑）

1. **需求与关联材料**
   - 直接放 PRD、联调记录或前置分析链接，不把需求全文抄一遍。
2. **需求拆分与整体节奏**
   - 几句话说清本次改造主线和上线节奏（如 `dryrun → AB 实验 → 推全 → 存量回扫`）。
   - 列出**接入范围**（产品、链路/场景、地区）和**策略/标签优先级表**。
   - 有多条识别或执行路径时，先放一张简单流程图说明怎么统一实现（例如“方式一其实就是没有小模型的方式二，合在一起写”）。
3. **开发改造（按服务或调用链拆开写）**
   - 跨服务改动按上下游顺序分节（如 `上游发消息 → 中游消费 → 下游回调处置`；有消费侧/读侧配合就单列一小节），说清每端各自干什么。
   - **画板或双栏标出接入位置**：解释调用链、决策流转或多条链路接入位置时，优先用**画板（Whiteboard）**或并列双栏标出新旧节点顺序（用 `新` 标出新增模块），替代大段文字。
   - **给出可对照落地的核心代码**：贴出关键结构体、函数签名和核心控制流骨架，注释只写设计意图、兜底原因和跨端约定，不贴大段无关样板代码。
4. **协议、动态配置与写入字段**
   - **IDL 与消息协议**：写清 IDL/Struct 新增字段、MQ/HTTP 字段表、完整 JSON 样例，以及上游字段到下游回调字段的映射表。
   - **动态配置明细**：写清配置平台和载体（如 TCC / Dolphin / 规则中心）、key 命名、规则顺序表（`顺序 | 规则名 | 表达式 | 返回结果`）、生效地区和上线前的安全初始值（如初始放量 0%、默认 dryrun）。
   - **多阶段写入与副作用对照**：涉及 `dryrun / abtest / punish / compute_only / backscan` 等多种模式时，用表格并排列出各阶段写哪些字段、动不动真实状态，并附 JSON 样例；多条规则先后命中时，写清保留哪条还是互相覆盖。
5. **放量、AB 实验与错误处理**
   - 说明放量分桶怎么算（如按主 ID 取模保证同一条数据判定稳定）、在什么时候算，以及 `compute_only / backscan` 怎么跳过放量。
   - 写清 AB 开关读取路径、实验组/对照组行为、双端同值约束和豁免条件（如作者本人豁免）。
   - **错误分级与强弱依赖**：按投递、消费、回调分别列出哪些错**记录后跳过/降级**，哪些错**强依赖向上报错或返回 500 触发重试**。
6. **指标与看板**
   - 用表格列出监控指标（`指标名 | 维度与口径 | 看什么问题`）。**把“规则正常返回（如 `dryrun`）”和“配置缺失/解析降级（如 `judge_fail` / `skip_no_config`）”拆成两个值打点**，漏配时看板一眼能看出来。
   - 贴出看板链接、关键筛选变量和排查组合（如错误 QPS 配失败率一起看，避免放量变化干扰）。
7. **存量回扫与耗时估算（涉及存量时）**
   - 写清回扫范围和过滤口径，附上盘点 SQL/数据量，按单模型或下游 QPS 上限算出不同 QPS 下的**耗时估算表**，提醒回扫和线上流量抢资源的问题。
8. **Timeline、Checklist 与上线顺序**
   - Checklist 列出配置、权限、开发、看板、dryrun、实验、推全、回扫等上线准备项。
   - 按依赖顺序列出上线步骤（如先合 IDL → 上消费/回调 → 上生产端与配置 → 低比例 dryrun 验证 → 切 punish 与回扫）。
   - 评审中还没拍板的边界问题可以集中列待确认项；定稿时把已确认的结论直接写回正文。

## 详略取舍

- **必须写透**：不写就会让人理解偏、或两端写出不同行为的边界条件（如顺序命中、大小写匹配、字段解析容错、只有命中违规才加载全量上下文）。
- **一句带过**：常规字段校验、基础格式转换、已经说明照抄的老 loader/helper 内部细节。

## 画板绘制规范（极简原生流程图）

画或改技术方案画板前，先看示例图对齐风格：
- 多路径对照：[多路径对比示例](examples/tech-flow-compare.jpg)
- 跨链路异步与回调：[异步回调链路示例](examples/tech-async-callback.jpg)

绘制要求：
- **只用最基础图形**：只用矩形、菱形判断、圆柱存储、分区框和连线箭头；**禁用装饰图标、角标、拆碎的独立文本框和多层叠加卡片**，保证重点突出、改图省事。
- **靠图形表达，框里只写短词**：用分区、箭头方向、实虚线（实线主流程 vs 虚线异步/回调、虚线框=复用老基建）和少量颜色直接表达逻辑；不在图上堆长段文字或大块说明气泡，完整参数留在正文和表格里。
- **别把图塞满**：控制单张图的节点数，避免窄框文字挤成多行或连线压字、压分区标题。
